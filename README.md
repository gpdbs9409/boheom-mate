# 보험메이트 (boheom-mate) — 실손보험 약관 상담 에이전트

실손의료보험 약관을 읽고 상담하는 **AI 에이전트**입니다.
사용자가 "감기로 동네 병원 갔는데 실손 돼요?", "급여로 3만원 냈는데 얼마 받아요?"처럼 물으면,
에이전트가 턴마다 **할 일을 스스로 판단해 도구를 호출**합니다. 약관을 검색해 근거와 함께 답하거나,
약관에서 뽑은 기준으로 보험금·남은 한도를 계산하거나, 면책 조항·청구 서류·약관 용어를 찾아 주거나, 정보가 모자라면 되묻습니다.
대화에서 들은 가입 시기·병원 종류·올해 받은 보험금 같은 정보는 **세션 메모리**에 남겨 다음 턴에 다시 묻지 않습니다.
고객이 "상담사에게 직접 문의하고 싶어요"라고 하면 채팅 안에서 **상담 신청**을 접수하고, 운영 채널에 **Slack MCP**로 새 접수 알림을 보냅니다.
약관 검색·계산 도구는 **MCP 서버**로도 내보내 다른 에이전트가 쓸 수 있습니다.
약관에서 근거를 찾지 못하면 지어내지 않고 "약관에서 확인할 수 없다"고 답합니다.

보험설계사는 답변의 근거 조항 원문과 핵심 문장을 바로 확인하고, 고객은 약관 용어 대신 쉬운 말로 결론을 먼저 듣습니다.

|---|---|---|
| 에이전트 | 턴마다 어떤 도구를 부를지, 되물을지 판단하고, 도구 결과를 보고 다시 판단해 답을 만든다. 시스템 프롬프트는 이번 턴에 붙은 도구의 규칙만으로 조립한다 | `ui/chat.py`, LangChain `ChatOpenAI.bind_tools`, `gpt-5.4-mini`, temperature 0 |
| 도구 레지스트리·디스패처 | 도구마다 스키마·프롬프트 규칙·사용 가능 조건·실행 함수·안내 문구 여부를 한곳에 둔다. 상품과 환경이 조건을 만족하는 도구만 붙이고, 없는 도구 호출은 거절하며, 도구 오류가 나도 대화를 이어 간다 | `ui/tools.py`(`REGISTRY`, `bound_tools`, `dispatch`) |
| 약관 RAG (`search_terms`) | 질문 요지 분석 → 원래 질문과 요지 검색어로 각각 하이브리드 검색 → 근거 조항만 써서 답변 | `core/rag.py`, LangChain `EnsembleRetriever`(벡터 검색: `OpenAIEmbeddings` + Chroma, 키워드 검색: `BM25Retriever` + kiwi 형태소 분석) |
| 약관 기반 계산 (`calculate_payout`, `remaining_limit`) | 상품 약관에서 뽑아 검증한 비율·공제금액·한도로 금액과 올해 남은 한도를 계산 | `core/policy_rules.py`(추출·검증, Rule_Set v2), `core/calculator.py`(계산) |
| 약관 조항 도구 | 면책 조항, 청구 서류·기한, 용어 정의를 조 제목으로 찾아 원문과 함께 돌려준다 | `core/articles.py`, `core/claim.py`, `core/glossary.py` |
| 병원 종류 판별 (`classify_hospital`) | 병원 이름으로 심평원 병원정보서비스를 조회해 계산용 병원 종류(의원/종합병원)로 바꾼다 | `integrations/hira_hospital.py`, `core/hospital.py` |
| 질병코드 찾기 (`lookup_kcd`) | 병명으로 로컬 KCD 색인에서 코드 후보를 찾고, 약관 면책 코드 범위와 대조한다 | `store/kcd_index.py`, `core/kcd.py` |
| 상담 신청 (`request_consultation`) | 문의 요약과 회신 이메일을 받아 접수번호를 만들고 접수 파일을 쓴 뒤, Slack MCP로 운영 채널에 알린다 | `core/consultation.py`, `store/outbox.py`, `integrations/mcp_client.py`(`langchain-mcp-adapters`) |

| 세션 메모리 | 한 대화 안에서 사용자가 말한 사실과 도구가 확인한 값을 정해진 칸에 저장하고 다음 턴 프롬프트에 넣는다 | `core/memory.py`, SQLite `session_memory` 표 |
| 근거 표시 | 근거 조항 원문을 정리하고 결론을 뒷받침한 문장만 강조 | `ui/display.py` |

## 에이전트 도구

에이전트는 아래 도구 중 **이번 상품과 환경에서 쓸 수 있는 것만** 받습니다. 조건을 만족하지 않는 도구는 프롬프트에도 들어가지 않으므로,
키나 색인이 없으면 그 도구가 없던 때와 똑같이 동작합니다.

| 도구 | 하는 일 | 붙는 조건 |
|---|---|---|
| `search_terms` | 약관을 검색해 근거 조항·핵심 문장과 함께 답한다 | 항상 |
| `calculate_payout` | 영수증 금액과 진료 조건으로 예상 보험금을 계산한다. 기본형은 `calculate`, 간편가입은 `calculate_simple`(급여·비급여 합계에서 "정액과 30% 중 큰 금액" 공제, 연간 공제 상한, 면책 3항목 0원) | 계산 기준이 모두 검증된 상품 |
| `remaining_limit` | 올해 받은 보험금·공제액으로 남은 한도를 계산하고, 한도는 계약해당일 기준 1년이라고 안내한다 | 계산 기준이 모두 검증된 상품 |
| `check_exclusions` | 임신·출산, 치과, 미용·성형처럼 면책일 수 있는 항목을 콕 집어 물을 때 보장 조항과 면책 조항을 함께 돌려준다 | 보장 조항과 면책 조항을 모두 찾은 상품 |
| `identify_generation` | 가입 연·월로 실손 세대(1~4세대)를 정한다 | 항상 |
| `claim_guide` | 청구 서류와 참고 청구 기한(약관 소멸시효 조항의 기간을 치료일에 더한 날)을 약관 조항과 함께 안내한다 | 청구 조항을 찾은 상품 |
| `explain_term` | "비급여가 뭐예요?"처럼 용어 뜻을 물으면 약관의 용어 정의 조항을 찾아 쉬운 말로 풀어 준다 | 용어 정의 조항을 찾은 상품 |
| `classify_hospital` | 병원 이름을 건강보험심사평가원 병원정보서비스에 조회해 계산용 병원 종류로 바꾼다. 후보가 여럿이면 고르게 하고, 실패하면 병원 종류를 되묻는다 | `.env`에 `HIRA_SERVICE_KEY`가 있을 때 |
| `lookup_kcd` | 사용자가 말한 병명으로 KCD 코드 후보를 찾고 약관 면책 코드 범위(면책/면책 예외 구분)와 대조한다. 병명은 외부로 보내지 않는다 | `data/kcd/` 색인이 있고, 면책 코드 범위가 검증된 상품 |
| `request_consultation` | 상담 신청을 접수한다(아래 "상담 신청") | 항상 |

- 각 도구 결과에는 계산·판정 근거가 된 약관 조항이 함께 오고, 금액·면책·청구 기한을 다루는 도구는 "참고용이며 보험사 심사로 확정된다"는 안내를 붙입니다.
- 도구를 늘려도 기존 답변이 바뀌지 않도록, 일반 보장 질문은 `search_terms`, 특정 항목의 면책 질문만 `check_exclusions`처럼 도구별 호출 규칙을 좁게 적었습니다.

### 상담 신청

- 사용자가 이번 턴에 사람 상담사와의 상담을 직접 요청했을 때만 부릅니다. 약관에서 답을 찾지 못한 턴에는 "원하시면 상담사 상담을 신청할 수 있어요" 한 줄만 붙입니다.
- 문의 요약과 회신 이메일이 있어야 접수합니다. 이메일은 사용자가 대화에 직접 쓴 주소만 받고, 형식이 틀리면 다시 묻습니다.
- 접수하면 `C-YYYYMMDD-XXXXXX` 형식의 접수번호를 만들고 답변 아래에 접수 내용(문의 요약, 회신 이메일, 선호 시간대)을 보여 줍니다.
- **이메일 상담 접수는 데모입니다.** 실제 메일은 보내지 않고 접수 파일을 `state/outbox/`에 쓰며, 24시간이 지나면 지웁니다. 한 대화에서 3건까지 접수할 수 있습니다.
- Slack 설정이 있으면 운영 채널에 "새 상담 접수" 알림을 1건 보냅니다. 알림에는 회신 이메일을 넣지 않습니다.

## 한 턴의 처리 순서

1. **메모리 불러오기**: 이 대화에서 기억한 내용(예: 가입 2018년 → 3세대, 동네 의원, 통원, 감기)을 에이전트 프롬프트에 넣습니다.
2. **할 일 판단**: 에이전트가 질문과 최근 대화를 보고 도구를 고릅니다. 이어지는 질문("대학병원이면요?")은
   앞 대화를 반영해 혼자 읽어도 뜻이 통하는 질문으로 바꿔 검색합니다.
3. **도구 1, 약관 검색(`search_terms`)**: 이 도구는 아래 용어로 설명합니다.
   - **질문 요지**: 질문을 정해진 보기(대상·원인·치료 형태·질문 유형·약관 용어)로 정리한 것. 화면에 "질문 요지"로 보입니다.
   - **요지 검색어**: 질문 요지를 약관 용어로 바꿔 만든 검색 문장. 표현이 달라도 뜻이 같은 질문은 같은 요지 검색어가 됩니다.
   - **하이브리드 검색**: 벡터 검색(뜻이 비슷한 조각)과 키워드 검색(BM25, 같은 단어가 든 조각)을 함께 쓰는 검색.

   원래 질문으로 한 번, 요지 검색어로 한 번 하이브리드 검색을 하고, 두 결과를 합쳐(원래 질문 결과에 2배 가중) 조각 8개를 고릅니다.
   원래 질문은 "1년에 최대" 같은 세부 표현을 살리고, 요지 검색어는 "보험가입금액 한도" 같은 약관의 조항 이름을 보탭니다.
   그 조각만 근거로 답하고, 근거마다 결론을 뒷받침한 문장을 함께 돌려줍니다.
4. **도구 2, 보험금 계산(`calculate_payout`)**: 영수증 금액과 진료 조건을 받아, 이 상품 약관에서 검증된 기준으로 코드가 계산합니다.
   가입 시기를 말했으면 세대도 코드가 정합니다(2009년 10월, 2017년 4월, 2021년 7월 기준).
   간편가입 상품은 메모리에 있는 올해 공제액·통원 횟수를 기본값으로 씁니다.
   면책 확인, 청구 안내, 용어 설명, 병원 종류 판별, 질병코드 대조, 상담 신청이 필요하면 해당 도구를 같은 방식으로 부릅니다.
5. **답변**: 결론을 먼저, 쉬운 말로 답하고 근거 원문·계산표·안내 문구를 함께 보여 줍니다.
6. **메모리 갱신**: 이번 턴에서 사용자가 말한 사실을 메모리에 반영합니다. 계산에 실제로 쓴 값과 도구가 확인한 값(가입 시기·세대, 올해 기수령액·공제액·통원 횟수, 계약해당일)은 정해진 칸으로만 옮깁니다.

## 신뢰성 장치

| 위험 | 막는 방법 |
|---|---|
| 근거 없는 답 | 실제 검색된 조각 번호만 근거로 인정하고, 유효한 근거가 없으면 정해진 안내 문구로 답합니다 |
| 근거 강조가 엉뚱함 | 핵심 문장은 근거 원문에 그대로 있을 때만 강조합니다. "보상합니다" 같은 단어 하나로는 칠하지 않습니다 |
| 의료비가 아닌 질문 | 차량 수리비·재산 손해 등은 비슷한 단어가 조항에 보여도 확인 불가로 답합니다 |
| 금액을 지어냄 | 금액은 코드가 계산합니다. 계산 기준값은 약관 원문 인용으로 검증된 것만 쓰고, 필수 값이 하나라도 검증되지 않은 상품은 계산하지 않습니다 |
| 다른 항목의 숫자를 인용 | 인용 구절 앞뒤에 그 항목을 가리키는 말(입원, 상급종합병원, MRI 등)이 있어야 하고, 종합병원 공제는 의원 공제보다 커야 합니다 |
| 면책을 단정 | 질병코드 대조 결과만으로 "보상되지 않는다"고 단정하지 않습니다. 코드는 병명으로 찾은 후보이고, 면책 예외 범위에 들면 "보상 가능성 있음"으로 표시합니다. 면책 코드 범위는 코드에 적어 두지 않고 약관 원문에서 뽑아 인용으로 검증합니다 |
| 외부로 나가는 정보 | 병원 정보 조회에는 병원 이름만 보내고 병명·가입 정보·메모리는 보내지 않습니다. 이 도구가 붙으면 화면에 외부 공공 API 전송 안내를 띄웁니다. 질병코드는 로컬 색인에서만 찾습니다. 외부 응답 원문은 메모리에 저장하지 않습니다 |
| 외부 도구 오남용 | Slack MCP 서버에서 메시지 보내기 도구만 씁니다. 서버가 다른 도구를 줘도 부르지 않고, LLM에게 MCP 도구를 주지 않습니다. 보낼 채널은 환경변수로 고정합니다 |
| 상담 신청의 개인정보 | 문의 요약과 선호 시간대의 주민번호·휴대전화번호·이메일은 자동으로 가립니다. 회신 이메일은 접수 파일에만 두고 메모리·Slack 알림·로그에 넣지 않습니다. 접수 파일은 24시간 뒤 지우고, 한 대화에서 3건까지만 받습니다 |
| 키 노출 | API 키와 토큰은 `.env`에만 두고 로그·도구 결과·화면·오류 메시지에 넣지 않습니다 |
| 메모리가 틀림 | 메모리는 정해진 칸과 보기만 받습니다. 세대는 가입 연·월로 코드가 계산하고, 경계 연도에 월을 모르면 비워 둡니다. 개인정보는 적지 않고, 사용자가 "기억 지우기"로 지울 수 있습니다 |

기본 상품(KB 실손의료비보장보험 26.09)에서 자동으로 뽑은 계산 기준 22개는 사람이 확인한 값과 모두 일치합니다.
간편가입 상품은 공제금액·연간 공제 상한 등 11개 값과 면책 3항목(도수치료·주사·MRI)을 같은 방식(Rule_Set v2)으로 원문 인용에 맞춰 검증합니다.

## 정확도

평가셋 `eval/questions.json`(개발용 20문항 + 최종 확인용 10문항)으로 바꿀 때마다 점수를 비교했습니다.
각 문항에는 정답 조각에 반드시 들어 있어야 할 약관 문구가 붙어 있고, 검색된 상위 8개 조각에 그 문구가 있으면 적중입니다.
이어지는 상담은 `eval/conversations.json`으로 평가합니다. 기존 시나리오 8개(11턴)에 더해, 도구마다 "이 질문이면 이 도구를 불러야 한다/부르면 안 된다"를 채점하는 tools 그룹이 있습니다.
실험별 가설, 변경 내용, 결과 파일, 판정은 [`eval/EXPERIMENTS.md`](eval/EXPERIMENTS.md)에 있습니다.

### 도구 확장 회귀 확인 (E12~E18)

도구를 단계별로 붙일 때마다 같은 합격선을 확인했습니다. 합격선은 **거절 정확 100%, 검색 적중 94% 이상, 기존 11턴 11/11, 기존 턴의 도구 선택 오류 0**입니다.

| 실험 | 붙인 것 | 결과 |
|---|---|---|
| E12 | 도구 확장 전 기준선 | 합격선 기준값 (검색 94%, 거절 100%, 11/11, 도구 선택 오류 0) |

| E14 | 도구 레지스트리·디스패처 | 합격, 프롬프트 길이와 도구 선택이 E13과 같음 |
| E15 | 상담 신청 | 합격선은 지켰으나 채점 문구 문제로 1턴 실패해 보류 → E16에서 해결 |

정확도를 가장 크게 올린 것은 **하이브리드 검색(키워드 검색 BM25 추가)과 약관 구조에 맞춘 청킹**입니다.
LangChain 기본 설정(글자 수 청킹 + 벡터 검색만)은 같은 평가셋에서 47%였고,
약관 구조에 맞춘 청킹과 한국어 형태소 분석을 쓴 키워드 검색을 LangChain 검색기에 얹어 94%가 됐습니다.

## MCP 연동

보험메이트는 MCP(Model Context Protocol)를 두 방향으로 씁니다.

**MCP 서버: 다른 에이전트가 보험메이트 도구를 쓰게 내보내기** (`boheom_mate/mcp_server.py`)

다른 에이전트가 보험메이트의 약관 검색·계산을 표준 프로토콜로 부를 수 있게 여는 서버입니다. 현재는 로컬 stdio로만 열고 원격으로 공개하지 않습니다.
앱 동작에는 필요하지 않습니다.

| 도구 | 하는 일 |
|---|---|
| `list_products` | 상담할 수 있는 약관 목록 |
| `search_terms` | 약관 검색 → 근거 조항·핵심 문장과 함께 답변 (근거 없으면 found=false) |
| `calculate_payout` | 약관에서 검증한 기준으로 예상 보험금 계산 |

읽기 전용이라 저장·전송·삭제를 하지 않고, 상담 신청 도구는 내보내지 않습니다.
Kiro, Claude Desktop 같은 MCP 클라이언트에 `.venv/bin/python -m boheom_mate.mcp_server`(stdio)를 등록하면 됩니다.

**MCP 클라이언트: 새 상담 접수를 Slack으로 알리기** (`integrations/mcp_client.py`)

| 기능 | MCP 서버 | 쓰는 도구 | 상태 |
|---|---|---|---|
| 새 상담 접수 알림(`consult_notice`) | [Slack 공식 MCP 서버](https://docs.slack.dev/ai/slack-mcp-server/) (`mcp.slack.com/mcp`) | 메시지 보내기 | `.env`에 `SLACK_MCP_USER_TOKEN`(MCP를 켠 Slack 앱의 사용자 토큰, chat:write), `SLACK_HANDOFF_CHANNEL_ID`를 넣으면 켜짐 |

- Slack MCP는 상담 접수 알림에만 씁니다. 설정이 없으면 알림 없이 접수만 합니다.
- 키를 넣은 뒤 `.venv/bin/python -m boheom_mate.integrations.mcp_client --check`로 연결과 보내기 도구를 확인할 수 있습니다(아무것도 보내지 않음).
- 도구 이름·입력 칸 이름이 조금 달라도 정해 둔 후보(메시지 보내기 도구만)에서 찾아 맞춥니다.
- 테스트는 가짜 MCP 서버(stdio)로 합니다. 허용 목록 밖 도구 거절, 채널 고정,
  토큰이 오류 메시지에 나오지 않는지를 확인합니다.

.venv/bin/python -m boheom_mate.jobs.build_kcd_index --check   # 색인 요약·샘플 조회
```

.venv/bin/python eval/run_eval.py                                  # 답변까지 포함한 평가 (20문항 × 3회)
.venv/bin/python eval/run_paraphrase.py --note "메모"              # 표현만 다른 질문의 근거 일치
.venv/bin/python eval/run_chat.py --note "메모"                    # 이어지는 상담·계산·쉬운 말·도구 선택
.venv/bin/python -m boheom_mate.mcp_server                         # 보험메이트 MCP 서버 (stdio)
```

## 배포

- AWS EC2(t3.micro, 서울)에서 systemd로 앱(`boheom-mate.service`), 주간 약관 확인(`weekly-check.timer`, 월 09:00 KST),
  승인 반영(`apply-approved.timer`, 5분마다)을 실행합니다.
- nginx가 HTTPS(Let's Encrypt, 자동 갱신)와 검색 노출용 메타 정보(title, description, robots, sitemap)를 처리합니다.
- 코드는 `deploy/push.sh`로 올리고, 약관·KCD 색인·벡터 DB·상태 파일(`data/`, `data/kcd/`, `chroma_db/`, `state/`)은 서버가 원본입니다.
- Slack 설정과 운영 절차는 [`docs/slack-setup.md`](docs/slack-setup.md)에 있습니다.
