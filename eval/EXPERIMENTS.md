# 실험 기록

정확도를 올리려고 바꾼 것과 그 결과를 순서대로 남긴다. 실험마다 결과 파일(`eval/results/`)이 있으니,
문항별로 무엇을 찾았는지는 그 파일의 `rows`에서 확인할 수 있다(`queries`, `keywords`, `retrieved`).

- 채점: 개발용(dev) 20문항 중 답이 있는 17문항. 최종 확인용(test) 10문항은 튜닝이 끝날 때까지 돌리지 않는다.
- 검색만 채점: `.venv/bin/python eval/run_eval.py --retrieval-only --note "실험 이름"`
- 표현 바꾸기 시험: `.venv/bin/python eval/run_paraphrase.py --note "실험 이름"` (`eval/paraphrases.json`, 6묶음 × 3문장)
- 지표
  - **근거 겹침**: 뜻이 같고 표현만 다른 질문끼리 상위 5개 조항이 얼마나 겹치는가(100%면 완전히 같음)
  - **1등 일치**: 표현만 다른 질문들이 모두 같은 조항을 1등으로 찾았는가
  - **검색 적중률**: 상위 8개 안에 정답 조각이 있는가
  - **상위 3 적중**: 상위 3개 안에 정답 조각이 있는가
  - **MRR**: 정답 조각의 순위 점수(1등 1, 2등 0.5, 3등 0.33 … 못 찾으면 0의 평균. 1.00이 만점)

## E1 약관 구역 꼬리표 + 조항 경계 수정

- 결과: `results/20261016_235919_dev_retrieval.json`
- 발견한 문제(데이터 품질)

  2. 특약2의 제3조(보상내용, 공제금액 표)가 본문 속 인용 "제5조의2([별표5]…)"를 조항 제목으로 잘못 인식해
     엉뚱한 제목 아래 묻혀 있었다. D13의 정답이 여기 있었다.
  3. 마지막 제도성 특약 조항이 뒤의 별표(용어의 정의, 장해분류표)를 통째로 끌고 있었다.
  4. 보통약관 제3조, 특약1 제3조, 특약2 제3조가 모두 "제3조"라서 화면에서도 구분되지 않았다.

  구역이 바뀌는 곳에서 조항을 끊고, 대괄호로 시작하는 인용은 제목으로 보지 않는다.
  임베딩할 때 조각 앞에 "[구역] 제N조(제목)"을 붙였다.
- 결과: 적중률은 떨어졌지만(71→53%) MRR은 같았다. D05·D07·D10·D12는 1등으로 올라왔고 D08·D11·D15·D17은 놓쳤다.

  거의 같은 조각이 많아서, 벡터 검색만으로는 순위가 조금만 바뀌어도 8등 밖으로 밀린다.
- 판정: 1~4는 데이터 오류라서 점수와 상관없이 고친 상태를 유지한다. 벡터 검색만으로는 부족하다는 결론.

## E2 하이브리드 검색: 의미 검색 + 키워드 검색 (채택)

- 결과: `results/20261017_000302_dev_retrieval.json`
- 가설: "쌍꺼풀", "유독가스", "상급병실료"처럼 질문 속 단어가 약관에 그대로 있으면,
  단어가 겹치는지 세는 검색이 비슷한 조각 사이에서 정답을 더 잘 골라낸다.
- 바꾼 것
  1. **질문 분석(GPT)**: 질문 하나로 ① 약관 용어 문장과 ② 핵심 키워드 3~8개를 함께 뽑는다(`rag.analyze_question`).
  2. **형태소 분석(kiwi)**: 질문과 약관을 명사 단위로 자른다(`keyword_search.tokenize`).
     kiwi는 "비급여"를 "비+급여"로 쪼개서 급여/비급여 구분이 사라지므로, 붙어 있는 접두사·명사를 다시 합친 단어도 넣는다.
     예: "비급여 병실료의" → 비급여, 급여, 병실료, 병실
  3. **키워드 검색(BM25)**: 질문 단어가 조각에 많이 나오고, 약관 전체에서 드문 단어일수록 높은 점수를 준다.
  4. **순위 합치기(RRF)**: 벡터 검색 3개와 키워드 검색 1개의 순위를 합친다. 각 검색에서 20개씩 후보를 받는다.
- 결과: 적중 94%, 상위 3 82%, MRR 0.59. 17문항 중 16문항을 찾았다.
- 남은 실패: D17(1인실 상급병실료 차액). 정답 문구 "비급여 병실료의 50%"가 특약1 제3조에 있는데,
  "상급병실료"가 많이 나오는 다른 조각들(국민건강보험 규칙의 비급여 대상 등)에 밀린다.

## E3 질문 요지를 정해진 보기에서 고르기

- 결과: `results/20261017_001102_dev_retrieval.json`, `results/20261017_000919_paraphrase.json`
- 계기: 사용자가 "독감걸렸는데 어떤 보장 받을수있는지"와 "저 그럼 독감걸렸는데 받을수있나요?"의 근거가 다르다고 알려 줬다.
  추적해 보니 GPT가 뽑은 키워드는 두 질문이 똑같았다. 갈라진 곳은 그 뒤였다.
  - 벡터 검색에 원래 질문 문장도 넣는데, "어떤 보장"과 "받을 수 있나요"는 문장 의미가 달라서 다른 조각이 올라왔다
    ("받을 수 있나요"는 "보상하지 않는 사항" 조각과 가깝다).
  - GPT가 쓴 검색 문장도 "… 보상"과 "… 보상 가능 여부"로 조금 달랐다.
- 측정: 뜻이 같은 질문 3개씩 6묶음을 만들어(`paraphrases.json`) 근거가 얼마나 겹치는지 쟀다. E2는 24%였다.
- 바꾼 것
  - GPT가 자유롭게 쓰지 않고 정해진 보기에서 고른다(`rag.analyze_question`).
    대상(질문 속 명사 그대로) / 원인(질병·상해·해당없음) / 치료(입원·통원·처방조제) /
    질문 유형(보상여부·보상금액·보상한도·청구절차·지급시기·청구기한·해지환급·청약철회·보험료·갱신·기타) / 약관 용어
  - "받을 수 있나요", "보장되나요", "청구 되나요", "어떤 보장"은 모두 "보상여부"로 고르게 했다.
  - 검색어는 원래 질문이 아니라 이 요지로 만든다(`rag.build_queries`). 질문 유형마다 꼭 봐야 할 조항 이름을 붙인다
    (보상여부 → "보장종목별 보상내용 보상하지 않는 사항").
  - 화면에 "질문 요지: 독감 · 질병 · 통원 · 보상여부"를 보여 줘서 GPT가 어떻게 이해했는지 사람이 확인할 수 있게 했다.
- 결과: 근거 겹침 24% → 73%, 1등 일치 33% → 83%. 두 독감 질문은 이제 같은 요지, 같은 검색어, 같은 근거를 갖는다.
  하지만 검색 적중은 94% → 76%로 떨어졌다. 질문의 세부 표현("1년에 몇 번", "맹장")이 요지로 줄어들면서 사라졌다.
  - 못 찾은 문항: D14(도수치료 횟수 한도, 정답 "50회"가 19등), D16(맹장: 치료 형태를 고르지 않아 보통약관 제3조를 놓침), D17
- 버그 수정: "사은품 주나요?"처럼 요지가 비는 질문은 검색어가 없어서 오류가 났다. 이 경우 원래 질문으로 찾는다.

## E4 질문 유형별 필수 조항 (채택)

- 결과: `results/20261017_001934_dev_retrieval.json`, `results/20261017_001959_paraphrase.json`
- 가설: 보상 담당자는 "보상되나요?"를 받으면 보상 조항과 면책 조항을 항상 함께 본다.
  검색 순위에 맡기지 않고 이 조항들을 반드시 후보에 넣으면, 표현이 달라도 같은 조항이 들어와 일관성과 정확도가 함께 오를 것이다.
- 바꾼 것(`rag.REQUIRED_ARTICLES`)
  - 보상여부 → 보장종목별 보상내용 + 보상하지 않는 사항
  - 보상금액 → 보장종목별 보상내용
  - 보상한도 → 보장종목별 보상내용 + 보험가입금액 한도
  - 보통약관, 특약1, 특약2에서 해당 조항의 조각 중 질문과 가장 가까운 것(의미+키워드 RRF)을 하나씩 먼저 넣고,
    남은 자리를 기존 검색 순위로 채운다. 전체 개수는 8개로 같아서 E3b와 공정하게 비교된다.
- 결과: 적중 82%와 상위 3 76%는 그대로, MRR 0.60 → 0.63, 근거 겹침 54% → 58%. 나빠진 지표가 없어 채택한다.
- 한계: D16(맹장)은 보통약관 제3조가 들어오지만, 6조각 중 정답 문구가 있는 조각이 아닌 다른 조각이 뽑힌다.
  조항은 맞는데 조각이 틀리는 문제라서, 다음에는 필수 조항의 조각을 여러 개 넣거나 조각 경계를 표의 행 단위로 바꾸는 방안을 본다.

## 확인한 것: GPT의 질문 분석은 얼마나 일정한가

같은 질문을 캐시 없이 3번씩 분석시켰다. 핵심 단어(맹장, 질병, 입원, 수술 / 1인실, 상급병실료 차액 / 도수치료, 비급여)는
매번 같았지만, 뒤쪽 보조 단어("보험금 지급", "급여", "보상하지 않는 사항" 등)는 바뀌었다.
앱은 한 번 분석한 질문을 기억해 두므로 같은 질문에는 같은 결과가 나온다. 하지만 표현만 조금 다른 질문은 다시 분석한다.
