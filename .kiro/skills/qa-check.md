# 품질 점검(QA) 절차

목표: "검증과 테스트 작성"에 집중한다. 이 절차는 **프로덕션 코드를 임의로 리팩토링하지 않는다**
(쪼개면 좋겠다는 제안은 하되, 실제 구조 변경은 사용자/별도 작업으로 분리).

## 1단계: 단위 분석 + 테스트
1. 대상 코드를 읽고 순수 함수(입력→출력이 결정적인 부분)와 외부 의존(OpenAI·Slack·파일IO·DB)을 구분한다.
2. 외부 의존은 mock/대역으로 격리한다(이 프로젝트의 기존 테스트가 FakeSlack·temp dir를 쓰는 방식을 따른다).
3. 함수마다 대표 입력 + 경계 입력으로 테스트를 만든다. 기존 테스트 스타일을 따른다
   (pytest 없이 `.venv/bin/python tests/test_xxx.py`, 성공 시 `OK`/`NN/NN 통과`).

## 2단계: 예외값 발굴 (LLM 강점)
4. "이 함수가 뭘 놓치는가"를 추론해 엣지케이스를 만든다:
   빈 입력, 0/음수, 아주 큰 값, 깨진 PDF, 0원 영수증, 경계값(공제·한도 경계),
   한글/유니코드, None 셀, 방문 횟수 0 등.
5. 순수 함수는 Hypothesis 속성 기반 테스트로 "모든 입력에서 성립할 불변식"을 검증한다(최소 100회).

## 3단계: 통합 테스트
6. 쪼갠 단위들이 함께 도는 흐름(질문→검색→계산→답변, 주간확인→승인→반영)을 점검한다.
7. RAG 품질 변화는 skill `eval-rag`로 전후 비교한다(회귀 금지).

## 보고
8. 통과/실패, 발견한 엣지케이스, 커버 안 된 부분, 프로덕션 코드에 제안할 리팩토링을 요약한다.
   실제 리팩토링 실행 여부는 사용자가 결정한다.
