# RAG 평가·회귀 확인 절차

검색·프롬프트·청킹·계산식 등 답변 품질에 영향을 주는 변경을 하면 반드시 따른다.
"감"이 아니라 숫자로 채택을 판단한다.

## 변경 전: 기준선 측정
1. 변경 전 상태에서 dev 평가를 돌려 기준선을 저장한다.
   `.venv/bin/python eval/run_eval.py --retrieval-only --split dev --note "기준선: 변경 전"`
2. 결과 파일(`eval/results/..._dev_retrieval.json`)에서 **검색 적중한 문항 집합**을 기록한다(회귀 비교 기준).

## 변경 후: 재측정
3. 변경·재색인 후 같은 조건으로 다시 돌린다.
   `.venv/bin/python eval/run_eval.py --retrieval-only --split dev --note "변경 내용"`
4. 비교 지표: 검색 적중률, 상위 3 적중, MRR. 표현만 다른 질문 일관성은 `run_paraphrase.py`.
5. 답변 생성까지 보려면 `--retrieval-only` 없이 돌려 거절 정확도·답변 키워드도 확인한다.

## 판정 규칙
- **채택 조건**: 목표 지표가 오르고, 기준선에서 적중했던 문항이 **하나도 떨어지지 않음**(회귀 없음).
- 특히 거절 정확도(없는 질문을 "확인 불가"로 답하는지)가 떨어지면 안 된다(안전 규칙).
- test 분할(10문항)은 튜닝이 끝날 때까지 돌리지 않는다.

## 기록
6. 가설·바꾼 것·결과 파일·판정을 `eval/EXPERIMENTS.md`에 실험(E번호)으로 남긴다.
7. 최종 판정은 사용자가 확인한다.

## 주의
- 평가셋 정답 숫자를 `glossary.py`에 넣으면 점수가 부풀려진다. 넣지 않는다.
- OpenAI API 비용이 든다. 검색만 보면 `--retrieval-only`가 빠르고 싸다.
