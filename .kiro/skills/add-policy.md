# 약관 추가 절차

새 약관 PDF를 서비스에 반영할 때 따른다. 목표: 조항이 올바르게 잘리고, 검색 품질이 떨어지지 않게 색인한다.

## 사전 확인
1. 텍스트 추출형 PDF인지 확인한다. 스캔 이미지 PDF는 `pypdf`로 텍스트가 안 나오므로 지원하지 않는다.
   - 확인: `.venv/bin/python -c "from boheom_mate.core import ingest; print(len(ingest.extract_text('data/파일명.pdf')))"` 가 충분히 큰 글자 수를 내는지.
2. 출처 URL과 판(버전, YY.MM)을 기록한다. 파일명 규칙을 따른다.

## 분할 점검 (색인 전)
3. `split_check`로 조항이 제대로 잘렸는지 먼저 본다(조각 수, 구역 분포, 의심 조항).
   - 기준 약관(25478)용으로 만든 구역 판별이 다른 상품(간편가입 등)에서 틀어질 수 있음을 유의한다.
4. 문제가 보이면 색인하지 말고 `ingest.find_sections`/`split_articles` 조정을 검토한다.

## 색인
5. 기준 약관만 다시 넣을 때는 전체 `ingest.py`가 아니라 `build_index`를 직접 호출한다
   (나머지 상품을 지우지 않기 위해). 같은 `source`는 교체된다.
6. 색인 후 상품 목록(`products`)에 등록되는지 확인한다(주간 확인 흐름이면 승인 후 자동 등록).

## 품질 확인 (필수)
7. 색인 후 반드시 평가를 돌려 검색 품질을 확인한다 → skill `eval-rag` 참고.
8. 결과가 기준선보다 나빠지면 색인을 되돌리거나 분할을 고친다.

## 주의
- OpenAI 임베딩 API를 호출하므로 비용이 든다. 전체 재색인(`ingest.py`)은 꼭 필요할 때만.
- 약관 PDF(`data/*.pdf`)는 git에 올리지 않는다.
